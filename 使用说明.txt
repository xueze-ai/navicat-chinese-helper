Navicat 中文助手 · 使用说明
================================================================

【这是什么】

一个独立的小工具。它盯住 Navicat 的「信息」面板，你在 Navicat 里执行 SQL 之后，
面板里出现的英文报错会被自动翻译成中文，显示在工具窗口里。

全程不需要复制、不需要粘贴、不需要额外装任何东西。

默认只用本地词库翻译，完全不联网、不需要配置。
如果想让程序顺便讲清「为什么错、怎么查、怎么修」，可以自己填一个 AI 接口（可选，见下面
【用 AI 帮你分析报错】一节），不填就永远不会联网。


【怎么用】

1. 双击「Navicat中文助手.exe」。窗口会出现在屏幕右下角，并且一直置顶。
2. 正常使用 Navicat，执行你的 SQL。
3. 每执行一次，工具窗口里就会多一条，长这样：

   ── 11:10:08 ──────────────────────────────
   执行：USE dcsefde
   【错误 1049】未知数据库 'dcsefde'
       建议：数据库名拼写错误，或该库不存在
       原文：1049 - Unknown database 'dcsefde'
   耗时： 0.001s

   翻译在「【错误 编码】」那一行；下面灰色的是原始英文，方便对照。
   执行成功、没有报错时会显示【执行成功】没有报错。


【窗口上的按钮】

  暂停      临时停止监听（再点一次继续）
  清空      清空当前显示的内容（不影响 Navicat）
  复制全部  把窗口里全部内容复制到剪贴板
  词库      用记事本打开词库文件，可以自己补充词条
  载入词库  改完词库后点一下，不用重启程序
  AI设置    配置 AI 接口（地址、密钥、模型、单价），里面还能「测试连接」
  置顶      让窗口始终显示在最前面
  用量统计  最右边的按钮，看 AI 花了多少钱、用了多少 token

不想用的时候直接关窗口，它会最小化到右下角托盘；右键托盘图标可以退出。


【用 AI 帮你分析报错（可选）】

词库只能告诉你「这句话是什么意思」，AI 能接着说清「为什么错、怎么查、怎么改」。

不配也能用：不填密钥，程序就完全不联网，只做词库翻译。

  1. 点窗口上的「AI设置」按钮；
  2. 填这几项（问给你密钥的人要，或者自己到服务商控制台开一个）：

       接口地址      OpenAI 兼容地址，到 /v1 为止，例如
                     https://xxx.cn-beijing.maas.aliyuncs.com/compatible-mode/v1
       密钥          服务商给的 key（窗口里打码显示，可以点「显示」核对）
       模型          例如 qwen-flash
       输入单价      元 / 百万 tokens（用来估算花费，填 0 就只统计 token）
       输出单价      元 / 百万 tokens
       最大输出      tokens，默认 1200；回答说一半被截断时把它调大

  3. 点「测试连接」。它会真的发一次请求回来，成功会显示「连接成功」，
     失败会告你是地址、密钥还是模型名的问题。
  4. 设置会存在程序目录的「AI配置.txt」里，下次启动自动读。

配上之后，每条报错下面会多一段彩色的分析，长这样：

   【错误 1822】添加外键失败：父表 'dept' 中缺少约束 'emp_ibfk_1' 所需的索引
   【AI 分析 · 需处理】外键约束要求被引用的列（dept.dname）必须有索引，但当前 dept 表中
                       dname 列没有索引
       先这样检查：
         1. 执行 SHOW INDEX FROM `dept` 查看 dname 列是否有索引
         2. 确认 dept 表中 dname 列是否已建立唯一索引或普通索引
       然后这样解决：
         1. ALTER TABLE `dept` ADD INDEX `idx_dname` (`dname`);
         2. 如果 dname 应为唯一值，建议用：ALTER TABLE `dept` ADD UNIQUE INDEX `uk_dname` (`dname`);
       避坑：被引用的列（父表）必须有索引才能作为外键目标，否则无法创建外键约束

标题里的级别用颜色区分，一眼看出要不要马上处理：

   严重    红色    连不上库、权限不足、数据损坏或可能丢数据
   需处理  橙色    要改表结构、索引、约束、外键、建表语句
   一般    黄色    数据值重复、字段名拼写、类型不匹配、SQL 写错
   提示    绿色    不是错误，只是提示

关于花费：
  · 解释一条报错大约 0.0008 元（默认单价下，一千条不到 1 块钱）；
  · 同一条错误（错误码 + 英文原文 + SQL 都一样）只会问一次，之后直接复用，
    窗口里会标注「复用上次的分析，没再花钱」；
  · 想知道花了多少，点最右边的「用量统计」：里面分「本次会话」和「累计」，
    列出调用次数、输入/输出/合计 token 和估算花费，还能清空累计。
    累计数存在「AI用量.txt」里，关了程序也不会丢。
  · 状态栏也会实时显示一行，例如：AI 4 次 · 2865 tokens · 0.0014 元

几点要留意的：
  · 每次分析只会把你出错的那条 SQL、错误码 + 英文原文、以及本地词库的中文大意发出去，
    不会发你的表数据；
  · AI 给的是排查建议，涉及改表结构、删数据这类语句，执行前请自己再确认一遍；
  · 「AI配置.txt」里有你的密钥，别发到群里或提交到公开仓库（本目录的 .gitignore 已忽略它）。


【它是怎么做到的】

Navicat 官方没有提供插件接口，所以做不成真正的 Navicat 插件，只能用外挂的方式：

  1. 用系统自带的 Win32 接口（EnumChildWindows）找到 Navicat「信息」面板那个文本框；
  2. 直接取它的文字，所以不需要截图识别（OCR），也不需要你复制粘贴；
  3. 解析出错误码和英文原文，去本地词库查中文，显示出来。

词典里目前有 472 个 MySQL 错误码（以服务端 1xxx / 2xxx / 3xxx 段为主）。中文说法是照着 MySQL 官方
（perror.exe / share\messages_to_clients.txt）的英文模板逐条写的，不是机翻。
碰到词库里没有的错误码，它会原样显示英文并标注「词库暂无此码」。

开了 AI 之后会再多一步：把「出错的那条 SQL + 错误码 + 英文原文 + 词库中文大意」发给你填的接口，
要求模型只回一个 JSON（原因 / 检查 / 解决 / 避坑），程序再按 JSON 渲染成带颜色的分条列表——
所以那些编号和配色是程序画的，不是模型随便发挥；万一模型没按格式回，程序会把能拿到的字段抽出来
显示并标注，实在解析不出来才贴原话，不会假装成功。


【想增加词条？】

用记事本打开「词库.txt」，一行一条，三列，用 Tab 键分隔：

    错误码 <Tab> 中文说法 <Tab> 建议

  例如：
    1049    未知数据库 '{1}'    数据库名拼写错误，或该库不存在

写法说明：
  {1} {2} ...      英文原文里第 1、2 个「单引号参数」的值
  {N1} {N2} ...    英文原文里第 1、2 个数字
  以 # 开头的行是注释，不会被读取
  同一个错误码可以写多行（对应英文的不同说法），程序会自动挑参数能套上的那条

想查到某个错误码的官方英文原文，可以在命令行里跑（按你自己的 MySQL 安装路径）：

    "E:\IDEA\MySQL\MySQL Server 8.0\bin\perror.exe" 1049 1062

改完词库，点窗口上的「载入词库」即可生效。


【开机自动启动（可选）】

  1. 右键「Navicat中文助手.exe」→ 发送到 → 桌面快捷方式；
  2. 按 Win+R，输入 shell:startup 回车；
  3. 把桌面上的快捷方式拖进打开的文件夹里。


【常见问题】

Q：窗口里一直没内容？
A：先在 Navicat 里随便执行一句会报错的 SQL（比如 USE 一个不存在的库）试试。
   另外确认 Navicat 底部的「信息」面板是打开的（和「状态」「剖析」并列的那个页签）。
   工具状态栏会显示「已连接 Navicat（N 个结果面板）」，说明已认出面板。

Q：双击 exe 没反应 / 提示缺东西？
A：本工具用系统自带的 .NET Framework 4.x，Windows 10/11 默认就有。
   若确实弹出缺 .NET 的提示，装一下 .NET Framework 4.8 即可。

Q：会不会把数据改坏？
A：不会。工具只读 Navicat 面板上的文字，从不向 Navicat 写入任何内容。

Q：Navicat 关掉再打开还能用吗？
A：可以，工具会自动重新找到新窗口，不用重启。

Q：AI 分析一直不出来？
A：看状态栏：显示「AI 未开启」就去「AI设置」打开开关；显示「AI 待配置」是密钥或地址没填。
   再点一次「测试连接」，它会直接告你是哪里不对。网络慢时回答要等几秒，
   这期间日志里会显示「正在请 xxx 分析错误 1822 …」。

Q：AI 的回答显示到一半就没了？
A：被「最大输出 tokens」截断了。程序会尽量把已经拿到的内容显示出来并标注；
   想更完整，把「AI设置」里的最大输出调大（比如 2000）。


【目录里都有什么】

  Navicat中文助手.exe      主程序，双击运行
  词库.txt                 错误码中文词库，可以自己加
  AI配置.txt               AI 接口设置（里面有密钥，不要外传、不要上传仓库）
  AI用量.txt               AI 用量与花费的累计记录，程序自己维护
  AI自检.txt               用 --aitest 生成的自检报告（含 token 与花费）
  使用说明.txt             本文件
  NavicatChineseHelper.cs  源码（C#，想改功能改这个）
  编译.bat                 改完源码后双击它重新编译，生成新的 exe
  build.ps1                编译.bat 实际调用的脚本，一般不用直接运行
  自检结果.txt             自检输出，用来核对词库和翻译是否正确
  诊断日志.txt             排查用日志，只有加 --debug 参数启动时才会写入


【命令行参数（一般用不到）】

  Navicat中文助手.exe --selftest    不做监听，只跑一遍翻译自检并写 自检结果.txt
  Navicat中文助手.exe --aitest      真调用一次 AI 接口，生成 AI自检.txt（含 token 和花费）
  Navicat中文助手.exe --demo        不靠 Navicat，直接喂几条样例报错走完整流程（会真的调用 AI）
  Navicat中文助手.exe --debug       写 诊断日志.txt，用于排查读不到面板的问题
